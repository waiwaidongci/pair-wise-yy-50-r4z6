# 印刷拼版预检与放行批次平台

面向印刷生产团队的拼版工作台：拼版版本、打样结论与导出任务挂在**同一个放行批次**下，拼版员、色彩管理、生产主管按岗位签核，依据一改即作废重算，写盘故障不留半批。

## 技术栈

Vue 3 + PrimeVue + Pinia + Vue Router + TanStack Query + Axios（模拟 REST）+ Canvas + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev          # http://localhost:62050
npm run test:smoke   # 放行规则端到端冒烟（50 项断言）
npm run typecheck
npm run build
```

## 放行批次规则

- **发起即冻结**：创建批次时冻结版位哈希、纸张规格（出血/安全区/装订/纸纹）与色差依据（选定样张轮次、结论、ΔE）。
- **岗位权限**：三个签核槽位分别只允许拼版员 / 色彩管理 / 生产主管签；无权限提交返回 403 并写入审计。
- **双终端并发**：同岗位两人（终端 A/B）同时提交时同步临界区先到先得，后到者收到 409 版本/占用冲突，审计记录谁占用、谁被驳回。
- **改动即失效**：
  - 版位/出血改动 → 三岗签核全部作废；
  - 纸张规格改动 → 拼版、生产签核作废（色彩签核保留）；
  - 打样决定改动 → 色彩、生产签核作废（拼版签核保留）；
  - 同一事务内，未完成导出（排队/生成/中断）置「已失效」并保留分片进度，已完成任务不受影响；重新冻结并补签后按新依据重算。
- **旧草稿待复核**：打样未通过、ΔE > 2.0、存在阻断级预检错误或缺出血时发起，批次归「待复核」，不开放签核、不允许导出；补齐依据后重新冻结。
- **原子写盘与恢复**：每次状态变更走两阶段提交（临时区 → 主区 → 备份）。阶段 1 失败自动回到最后一致状态重放；阶段 2 失败直接采用临时区中的完整提交；启动时主区损坏从 tmp/bak 恢复，半截 JSON 一律丢弃。界面「写盘故障演练」可注入两种故障。
- **单一放行状态**：生产总览与导出队列（含模拟 Axios REST 层）读同一份 `release.state`，状态始终一致。

## 代码结构

```
src/release/
  types.ts        # 岗位/槽位/批次/签核/审计领域模型
  engine.ts       # 纯逻辑：冻结依据、签核(403/409)、作废重算、重新冻结
  persistence.ts  # 两阶段原子写盘、故障注入、启动恢复（不留半批）
src/stores/
  imposition.ts   # 页面/版位/纸张/打样草稿（旧 print-imposition-v1 自动迁移）
  release.ts      # 事务、依据漂移监听、导出队列、操作人/终端切换
src/api/
  registry.ts     # REST 与 UI 共享的任务注册表
  exportApi.ts    # Axios 适配器（模拟后端，同源放行状态）
test/release.smoke.ts  # 真实 Pinia + 内存 localStorage 的规则冒烟
```
